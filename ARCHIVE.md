## Two copies of the history

**Browsable.** `refs/heads/projects/<label>/<branch>` holds each project's
commits with paths moved under its folder. This is what makes `git log`,
`git log -p Demos/D1/src/…`, and GitHub's file history read naturally inside the
archive. `main` is a merge of these histories, so every commit is reachable from
the default branch.

**Exact.** `archives/<label>.bundle` is the original repository as published:
original commit hashes, original branch names, nothing rewritten. Bundles are
checked with `git bundle verify` when they are created.

## Restoring an original repository

```sh
git clone archives/D1.bundle d1-project
cd d1-project
git remote set-url origin git@github.com:m1stD3V/d1-project.git
git push --mirror origin
```

Because the bundle keeps the original hashes, a restored repository is
indistinguishable from the one it came from — same commits, same branches, same
tags. That is the escape hatch if a project ever needs to live on its own again.

To check that everything is present:

```sh
git bundle verify archives/D1.bundle
git log --oneline projects/D1/main | head
git log --oneline -- Demos/D1 | head
```

## Retirement

The `Sync project sources` workflow exists only while the individual
repositories are still the place where work happens. After they are archived and
deleted:

1. Delete `.github/workflows/sync.yml`.
2. Leave `archives/` in place — it is the provenance record.
3. Delete the empty originals on GitHub at your own pace; nothing on this site
   depends on them.
